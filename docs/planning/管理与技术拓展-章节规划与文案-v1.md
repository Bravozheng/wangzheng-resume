## 3. 三种组织方式与推荐

- **7个连续模块，保留因果关系（推荐）**：每个模块只回答一个问题，能同时展开管理行动、技术实践及真实证据。
- **5个压缩模块**：将资源与生成合并、视频与Skill合并。阅读更快，但技术方法和负责人判断的空间偏少。
- **沿14页逐页展示**：最容易对应PDF，连续阅读较长，荣誉照片和同类素材容易重复。

推荐以7个模块规划。模块不强制等于一屏，一处主状态加展开细节可占较长阅读空间；先确认静态主构图，后续再实现动态。

### 06 方法沉淀：AI判断与团队共享

来源：42页；此前AI视频分享提供质量判断的具体例子。

- 主标题：**把生成经验，写成可执行的方法。**

- 核心内容：输入需求 → 规则与约束 → 脚本/分镜输出 → 人工检查。
- 次级内容：AI项目总结分享，传播实际制作经验和问题处理方法。

构图：真实Skill局部与它实际生成的中间产物相邻展示，避免把整张代码截图当成一张无法阅读的装饰图。另一组空间用于真实的“问题—处理方式”证据，如长镜头拆为小动作、角色一致性检查、候选镜头筛选。

AI理解分为四个可核对维度：

- 业务适配：目标受众、内容目的与生成任务的关系。
- 生成控制：素材、风格、角色和镜头约束的组织。
- 流程组织：文本、图片、声音、视频与后期制作的衔接。
- 质量判断：可用性、一致性、错误修正，以及时间和成本约束。

分享材料中的排队时长、积分变化属于当时实践记录，若展示必须注明“当次制作记录”，不表述为当前产品价格或通用模型能力。

此模块和第五模块承担不同任务：第五模块说明生产如何运转，第六模块说明经验如何复用、判断如何被保留。没有现成代码证据前，不增写自动调用、自动评测、自动发布或多Agent系统等功能。
