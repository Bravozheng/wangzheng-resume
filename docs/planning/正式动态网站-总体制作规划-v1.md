# 正式动态网站：总体制作规划 v1

日期：2026-10-16。

用途：统筹首页快速入口、三个独立项目频道、静态稿转网页、动效与上线顺序。已确认的案例视觉与后续新增的网站外壳设计分别记录；本地首轮实现位于 `site/`，尚未公开发布。

## 1. 网站结构与阅读路径

建议首版采用一个首页、三个独立项目页，共四个主要页面：

| 页面 | 建议地址 | 阅读目的 |
| --- | --- | --- |
| 首页 | `/` | 认识王峥的定位，快速选择一个项目，访问简历与联系方式 |
| 平安健康智慧医生工作台 · BianQue | `/work/bianque/` | 理解复杂医疗产品、用户研究、系统标准与智能 SOP 的设计能力 |
| 体检履约平台体验升级 | `/work/health-check/` | 理解检前、检中、检后的服务体验和业务链路 |
| 设计管理与技术拓展 | `/work/design-leadership/` | 理解团队建设、资源体系、AI 工作流、管理方法和团队成果 |

三个项目可从首页分别进入、分别分享；项目内部按已确认顺序自然纵向滚动。第三部分独立开场。项目结尾可提供其他项目入口，由读者选择进入，不把下一个项目直接拼接在当前长页下方。

首页承接简短个人介绍、简历下载和联系。首版不另增大型 About 页面。小马 AI 智能陪练保留为辅助 PDF 小链接；等用户提供新版文件后再接入，不使用历史提取版本，也不显示失效的下载按钮。

主要路径：

`首页定位 → 选择三个项目之一 → 项目概览与章节阅读 → 其他项目 / 返回首页 / 简历与联系`

## 2. 首页：四段式长页与三组项目入口

首页视觉基准：`output/visual-concepts/homepage-longform-v2/`。桌面包含开场、精选项目、个人与方法、经历荣誉与联系四段 3840 × 2160 画面；手机端另有四段 1170 × 2532 画面，不对桌面版做等比缩小。该方向已作为首轮网页实现基准。

### 方向选择

首页采用四段式长页建立完整门面：居中文字开场、精选项目、个人定位与设计方法、经历荣誉与联系。首屏使用医学细胞主题背景，经高斯模糊、降饱和与深色蒙层处理，避免与下方正式项目封面重复竞争；“向下浏览精选项目”滚动到下一段。

精选项目使用三个完整首屏作为主缩略图。桌面横向排列，手机纵向排列；整张项目卡片即为进入操作，不再设置 `01 / 03` 页码、左右箭头或重复的“进入项目”按钮。项目页内部仍按已确认的同屏交互呈现，不受首页入口排列影响。

### 桌面首页安排

- 开场：顶部使用英文姓名；核心主张与能力范围居中，使用已确认的医学细胞主题图作为模糊背景。
- 精选项目：三个项目使用各自完整首屏，统一 16:9 比例、顶线、文字层级与卡片间距；点击整张卡片进入项目。
- 个人与方法：以浅色编辑式版面呈现个人定位、经历跨度、重点案例数量与三条设计方法。
- 经历荣誉与联系：呈现现有作品集能核对的工作经历、团队项目荣誉、教育背景以及简历和联系入口。
- 正式网页的工作经历时间线必须补入虎扑：`2009—2015.09`，职位为“设计师 → 设计经理”。
- 首屏高度不足时优先保持文字可读并允许自然滚动，不把整屏等比缩小成难以阅读的小字。
- 首页不重复设计书架、完整奖杯证书或 AI 九步流程，只使用荣誉名称和项目数量建立可信度；完整证据仍留在对应项目页。

| 入口 | 展示名称与一句说明 | 主视觉来源 |
| --- | --- | --- |
| 工作台 | **平安健康智慧医生工作台**；复杂医疗场景中的系统与体验设计 | 已确认工作台开场中的电脑与真实界面 |
| 体检 | **体检履约平台体验升级**；贯通预约、到检与报告的服务体验 | 已确认的体检项目完整首屏 |
| 管理 | **设计管理与技术拓展**；让设计能力，成为团队的持续生产力 | 已确认女医生角色、数字化颗粒与 AI 视频视觉 |

三个入口直接使用已确认项目首屏，不再二次裁切或重组。三张图统一完整呈现，标题区高度一致，卡片间距和文字基线遵循同一栅格。

### 首页动态

- 首次进入：模糊项目背景缓慢清晰到既定状态，居中文字轻量进入；不自动替换文案或背景。
- 点击“向下浏览精选项目”平滑滚动到三个项目入口，减少动效模式直接跳转。
- 项目卡片悬停或键盘聚焦时只做轻微清晰度、边线和位移反馈，约 180–240ms；点击后进入对应项目页。
- 手机端三个完整封面纵向排列，整卡点按进入；不显示分页计数和左右箭头。

## 3. 全站导航与项目内导航

- 三个项目共用轻量顶部导航：回首页、切换项目、简历 / 联系。当前项目状态明确。
- 项目切换使用明确名称，进入新项目时从其开场开始；浏览器返回恢复此前阅读位置。
- 桌面端可提供收敛的章节索引。索引按研究、方案、验证等阅读阶段归组，不把所有静态帧都做成导航项。
- 项目关键章节使用稳定锚点，支持直接分享；跳转后标题不被顶部导航遮挡。
- 首屏下方继续使用已确认线性指引；它是滚动到内容的操作，外观和点击范围在全站统一。
- 主体使用自然滚动。只有需要连续解释状态的局部舞台短暂停留，始终可以继续向下阅读。

## 4. 三个项目的制作基准

### 项目一：BianQue

12 屏视觉定稿。页面顺序与源文件取自：

- `output/visual-concepts/two-projects-full-review-v2/视觉定稿记录.md`
- `output/visual-concepts/two-projects-full-review-v2/长图页面顺序.json`

沿用开场、同理心地图、画像、工作过程与情绪体验、策略、组件标准、人体档案、AI 与 SOP、专利、评估、项目认可、结尾的原顺序。

动效重点：真实画像在同一屏内通过“主任医师 / 医师助理 / 医师培训员”三个 Tab 手动切换，默认医师助理；切换时仅替换人物、目标、任务与阻力，页面不纵向平铺三张画像。其余重点包括工作流程中的当前阶段提示、组件与真实界面细节展开、人体档案与 SOP 的已提供状态展示、专利和奖项原图放大。阅读结论始终可见，交互用于展开证据。

第二屏英文保留 Helvetica Neue 无衬线斜体，中文与英文按确认的字组关系呈现。工作台始终作为 PC 产品展示。

### 项目二：体检履约

14 张定稿关键帧，使用同一 JSON 的 `physicalExam` 顺序。实际网页按内容模块组织：

1. 开场、链路诊断、设计发力点。
2. 3D 选购交互展示。
3. 原预约路径前后半程。
4. 三步预约总览与 01、02、03 的原位展开。
5. 检中即时动态。
6. 报告提醒与报告结构演变。
7. 项目结果与其他项目入口。

**14 张关键帧不等于 14 个强制全屏停顿。** 三步预约的总览、展开和归位属于同一组件的状态。沿用已确认的位置与关联，避免把用户应当点击切换的状态做成重复长屏。

动效重点：选购的拖动 / 缩放 / 器官与卡片状态；预约步骤原位展开与返回总览；签到详情与报告提醒的状态变化；报告从表单到人体可视化的演变。

当前已找到渲染图与静态状态素材，尚未在已检查的素材目录发现可直接用于网页的 3D 模型。先用真实关键帧、透明图层和局部交互实现已确认展示。任意角度实时旋转需要可用模型，不能用缺失视角假装实现；若后续取得模型再作为增强项。

## 5. 视频与自动轮播的统一规则

- 设计书架沿用约 4.5 秒停留、约 0.8 秒过渡；荣誉约 6 秒停留、约 0.45–0.65 秒过渡。仅进入视口后运行。
- 悬停、键盘聚焦、页面隐藏或离开视口时暂停；用户主动选择内容后优先保持当前项。正式版提供可聚焦的小型暂停 / 继续按钮，避免阅读被自动打断。
- 时间线、Tab、箭头与拖动使用同一状态来源，快速连续操作不会叠出两套文字或多个焦点。
- 减少动效模式关闭自动播放与装饰运动，保留全部内容与手动操作。
- AI 流程屏右侧顺序固定：家庭情景剧 01、家庭情景剧 02、平安家医服务、门诊预约服务。默认封面静止，点击在对应位置展开播放。
- 同一时间只播放一支视频；开始另一支时暂停前一支。声音由用户开启，离开章节暂停，返回时可继续。
- 更早“进入页面四视频循环 / 大型主视频舞台”的提案已被当前流程优先版式取代，不在正式版中同时叠加两套交互。

已找到原片：`tmp/case-intro-keynote-20261015/videos/video-01.mp4` 至 `video-04.mp4`，约 16–60MB / 支。

映射：家庭情景剧 01 → video-03；家庭情景剧 02 → video-02；平安家医服务 → video-01；门诊预约服务 → video-04。

正式制作时将源片移交到稳定素材目录并保留原件，再生成适合网页的播放版本和封面。页面初次加载封面，用户点播时加载对应视频，不把四支原片一起塞入首页。

## 6. 从定稿转为网页的方式

推荐可静态发布的组件化前端，页面内容预先生成，浏览器只为轮播、展开、播放和导航执行必要脚本。首版无需账号、数据库或内容管理后台。具体构建工具在搭建时选定，不影响已确认版式。

每屏按四层拆分：

1. **内容层**：真实文字、标题、数字、项目说明；可以选中、放大和响应式换行。
2. **素材层**：产品截图、角色、奖状、奖杯、视频；保留原始宽高比与清晰度。
3. **交互层**：导航、Tab、轮播、展开、播放器；真实按钮与链接，支持键盘和触屏。
4. **氛围层**：网格、微光、数字纹理；位于内容下方，不阻挡操作。

整屏 4K 图用于桌面视觉比对与过程预览，不作为所有正式页面的唯一内容载体。手机端重排图文顺序；复杂 PC 界面可以打开清晰大图查看，不伪造移动版工作台。

资产索引为每个模块记录：当前稿、原素材、文字来源、交互状态、移动布局、制作状态。素材使用稳定路径，正式站点不依赖桌面文件和临时目录。

## 7. 排版和动效的验收标准

- 全站明确页面边距、栏距、模块内边距和图文间距四级规则；同类组件使用同一规则，差异只来自已确认构图。
- 拉丁文字采用 Helvetica Neue / Helvetica 的字体栈；中文使用相容无衬线字体。若发布环境无 Helvetica，使用明确的无衬线后备字体并复查换行，不擅自打包无授权字体文件。
- 正文以实际 CSS 像素保证可读性，建议桌面 16–18px、手机至少 16px，重要说明不能因整屏缩放成为小字。具体字号根据确认稿的层级逐屏落位。
- 主图、标题、编号和说明按明确顶线或基线对齐。轮播不同内容长短使用稳定区域，切换时按钮和图片不跳位。
- 原图完整展示；入口封面可按用途单独构图，但原图中的项目内容与人物不可被随意替换。奖杯与奖状采用完整等比显示，取消人工椭圆阴影。
- 箭头可见、易识别，实际点击范围至少 44×44 CSS px；线性外观不意味着点击区也要细小。
- 仅保留有关系解释作用的局部动画；没有滚动劫持，没有必须看完整动画才能继续的阅读障碍。
- 桌面在 1440、1920 宽度检查图文对齐；手机在 390、430 宽度检查阅读与操作；较窄桌面另查一次无溢出状态。

## 8. 制作顺序与每轮可见交付

| 阶段 | 工作内容 | 可见交付与验收 |
| --- | --- | --- |

| C 排版样板 | 还原一个代表性左右内容屏，并先将已明确的荣誉轮播拆成真实网页组件 | 文字清晰，栅格与定稿对上，桌面 / 手机均能阅读；底部箭头好操作 |

| E 重点交互 | 体检预约原位展开、选购状态、书架轮播、荣誉轮播、视频播放，再补其他轻动效 | 输入与状态明确，手动操作优先；切换不乱位，视频与离屏动画能停止 |

首次搭建的验收目标是 B 阶段与一个 C 阶段样板：先形成首页与三个频道能访问的真实站点，并验证一屏的排版还原质量。后续以同一规则扩展正文与动效，不将全部内容和复杂交互压在第一轮。

2026-10-16 首轮进度：B 阶段已完成本地实现；C 阶段已完成用户画像、预约步骤、设计书架与团队荣誉四组同屏切换样板。下一轮进入 D 阶段正文扩展，并继续按确认稿逐屏校准。

## 9. 上线前需要补齐的少量内容

- 首页最终一句话定位、姓名展示方式和简历 / 联系区内容，在首页第一版实物中一起核对。
- 正式简历与小马辅助 PDF 使用用户指定文件；文件未提供前，相关下载入口不发布。
- 域名和托管服务在发布阶段确定；已有账号与域名优先复用。先完成可审阅版本，再决定公开发布地址。
- 内容核对保留“候选镜头片源”与“最终成片”的区别。AI 视频稿中的“单月”与早期材料的“近 3 周”统计口径在发布前核对；若未能确认，用“4 组视频”这一共同事实，不擅自写成月产能。

以上事项不妨碍页面骨架与已确认正文制作。
